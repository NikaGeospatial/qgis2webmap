{%- comment -%} Website analytics for the documentation site only. This measures visitors to nikageospatial.github.io/qgis2webmap - which pages they read, where they arrived from, how long they stay. It has nothing to do with the usage report an *exported map* sends: that comes from the OnlyMap runtime baked into the exported HTML, reports to a different service and a different PostHog project, and is described in `privacy.md`. Do not merge the two, and do not instrument anything inside the demo pages' map iframes - those maps already report for themselves, and counting them here would double up. Dormant until configured: with `posthog_key` empty in `_config.yml` this renders nothing at all, so `jekyll serve` on a laptop is silent and no local page view reaches the project. Cookieless by choice. `cookieless_mode: "always"` makes PostHog derive a visitor hash server side instead of storing anything on the reader's device - no cookies, no localStorage - so the site needs no consent banner while still counting unique visitors and following a reader from page to page. It requires "Cookieless server hash mode" to be switched on in the PostHog project's settings; without it, events are accepted but no one is counted. `identify()` does not work in this mode, and we never call it. The guides are plain Markdown on purpose (see `_config.yml`: the plugin's Help tab renders the same files through Qt). So nothing here may ask a `.md` file to carry a data attribute or a class. Every named event below is matched from the link's href instead, which is why the whole event list lives in this one file. {%- endcomment -%} {%- if site.posthog_key and site.posthog_key != "" -%} {%- endif -%}
